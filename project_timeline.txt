1. EXPLANATION OF EVERYTHING DONE TILL NOW (Week 2 Milestones)
--------------------------------------------------------------------------------
VoyagerAI is an Autonomous Multi-Agent AI Travel Planner. So far, the team has
completed the foundational structure (skeleton) of the application, ensuring a
fully integrated stack ready for agent intelligence:

* BACKEND SKELETON (FastAPI):
  - Built with FastAPI (Python 3.14/3.12) to handle asynchronous API requests
    efficiently (crucial for executing multi-agent workflows in parallel).
  - Configured database connectivity using SQLAlchemy 2.0 (ORM) and Alembic
    (database migration tool) to version control the database schema.
  - Implemented the initial core tables: "users" (for storing traveler accounts)
    and "trips" (for storing planned itineraries).

* FRONTEND SKELETON (Next.js 14):
  - Created a React-based web dashboard using TypeScript and Tailwind CSS.
  - Implemented a live connection monitor that queries the backend '/health'
    endpoint. It checks not just if the backend is awake, but runs a real SQL
    statement (SELECT 1) to verify database connectivity.
  - Added an interactive simulation panel to preview agent orchestration logs
    in real-time.

* DEVELOPMENT INFRASTRUCTURE:
  - Dockerized both services (`docker-compose.yml`) for seamless local setup.
  - Configured a local batch launcher (`run_dev.bat`) for non-Docker execution.
  - Established a GitHub Actions CI pipeline that automatically tests the backend
    and lint-checks/builds the frontend on every push or Pull Request.

3. HOW I GOT IT (Bug Fixes and Technical Adjustments)
--------------------------------------------------------------------------------
To achieve this clean output, we resolved 4 key issues across the codebase:

* BUG 1: FastAPI Static Directory Mounting Crash
  - Issue: The backend failed to start with a RuntimeError stating that the
    'backend/app/static' directory did not exist. This happened because FastAPI
    mounted the StaticFiles directory at module-import time (line 71 in main.py),
    while the directory creation was scheduled inside the asynchronous 'lifespan'
    function, which executes *after* import.
  - Fix: We added 'os.makedirs(static_dir_path, exist_ok=True)' immediately
    after resolving the path. This ensures the directory exists before FastAPI
    tries to mount it.

* BUG 2: Swagger/ReDoc OpenAPI URL Type Mismatch
  - Issue: Static type checkers (Pyright/Pylance) reported errors because
    'app.openapi_url' is typed as 'str | None' in FastAPI, but the swagger
    helper functions 'get_swagger_ui_html' and 'get_redoc_html' require a 'str'.
  - Fix: We added a safe fallback to the FastAPI default schema path:
    'openapi_url=app.openapi_url or "/openapi.json"'.

* BUG 3: VS Code / Pyright Import Errors
  - Issue: The IDE displayed red squiggly lines for backend imports (like
    'from app.core...'). This was because the IDE root was opened at
    'c:\AgenticAIProject', but Python paths were relative to the 'backend/' dir.
  - Fix: We updated 'pyrightconfig.json' at the workspace root to include
    '"extraPaths": ["backend"]'. This allows the IDE to correctly locate the
    modules and resolve imports.

* BUG 4: Next.js Frontend ESLint Double Quote Warning
  - Issue: Next.js build failed due to strict React entity checking on line 375
    in 'frontend/app/page.tsx' where double quotes was used directly in JSX
    ("Run Sample Agent Query").
  - Fix: Escaped the quotes using standard React HTML entities:
    '&quot;Run Sample Agent Query&quot;'.

4. WHY THIS APPROACH ONLY (Architectural Justification)
--------------------------------------------------------------------------------
When presenting to the team or leadership, here is the rationale behind our
design choices:

* FASTAPI + NEXT.JS:
  - FastAPI is built on top of Starlette and Pydantic, making it one of the
    fastest Python web frameworks. It supports native async/await, which is
    essential when we hook up multiple AI Agents waiting on concurrent network
    requests (Amadeus, Gemini, Google Places).
  - Next.js 14 App Router provides automatic route optimization, built-in SEO
    practices, and server-side components, ensuring the frontend loads instantly.

* ORM AND ALEMBIC MIGRATIONS:
  - Using SQLAlchemy 2.0 ensures we write clean, object-oriented Python code
    rather than raw SQL.
  - Alembic migrations ensure that any DB schema modifications are scripted.
    This guarantees that Yashraj, Hetvi, Shreyas, and Meet always run the exact
    same database tables on their local setups, avoiding "works on my machine"
    database conflicts.

* CDN FALLBACK FOR DOCS:
  - Downloading Swagger CSS/JS assets locally ensures that developers can review
    API structures even in poor network zones, offline settings, or when
    jsdelivr/cdnjs CDNs are unreachable.
